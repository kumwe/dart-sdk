# Documentation instructions

These instructions apply under `docs/` in addition to the repository-level `AGENTS.md`.

- Distinguish observed core behavior, adopted contracts, and proposals in every document.
- Treat `docs/status.md` as evidence-backed current state and `docs/roadmap.md` as future work.
- Keep core Version 2 and its gates separate from the proposed Version 3 Native Client Platform.
- Add or update an ADR when a change constrains package architecture, security, compatibility, or extension behavior.
- Keep local links valid and update `docs/README.md` when adding a primary document.
- Never describe a proposal or scaffold as released capability.
