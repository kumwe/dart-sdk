Date: 2026-09-07. Baseline `kumwe/dart-sdk@88f4c82d575d65005fc75e367bff9f4e0f65d056`; candidate [PR #7](https://github.com/kumwe/dart-sdk/pull/7). Read-only independent review of all 51 module exports in `lib/kumwe_sdk.dart`, their public declarations, and package test evidence. Baseline had 40 test files; the lifecycle candidate adds two. Final candidate CI is required on both the minimum and stable Dart versions. This is an ownership and focused behavior review, not complete line/branch/input coverage or full protocol certification.

## Concrete findings and independent reproduction

All seven findings are addressed in PR #7. The source-level review identified the defects before the fixes; the package now retains their regressions.

1. Session overlapping interactive A/B completed B before A adopted old A. A late old 401 refresh failure after new interactive success left a new token held but changed state to `reauthenticationRequired`. Independent script reproduced both; after generation changes it retained the new active session. Deferred disposal now waits current acquisition or generation-change notification, checks the held credential reference, and wakes on terminal sign-out. Independent targeted run: 12 lifecycle/transport tests passed.
2. `KumweClient.liveness()` and `KumweLiveness` had no caller/test anywhere; health probing is portable SDK behavior. Added success plus malformed product/status/non-200 refusal and anonymous configured-base routing. Readiness 200 and mismatched status/body are covered in the same bounded matrix.
3. `business_value_validator_test.dart` test named “a frozen field is refused on update only” supplied a mutable `issued_on` and asserted no immutable violation. Corrected the fixture to make the field writable and immutable, proving create acceptance and update refusal.
4. `KumweJsonValue._freeze` has depth 128 but direct tests proved cycles only. Added 128 acceptance and 129 refusal through public construction/parsing for array and object nesting.
5. Independently replayed `date` and `date-time` validation with 2025-02-29 and 2026-04-31: all incorrectly returned `isValid=true`. Valid 2024-02-29 also passed. Added strict Gregorian calendar validation for both formats; broader clock/offset/leap-second qualification remains explicitly separate.
6. Independently replayed admitted schema `{type:object, properties:{a:{},b:{}}, additionalProperties:false, dependentSchemas:{a:{required:[b]}}}` against `{a:1}`: `isValid=true`. Added enforcement through the existing recursive validator, including absent trigger, null-present trigger and boolean refusal cases.
7. Independently replayed business notes fragment `{type:string,maxLength:20,pattern:"["}`: malformed regex produced an empty business violation list because `_schemaViolations` swallowed `FormatException`. Now returns a visible schema refusal with no leaked input value or malformed pattern.

The independent reviewer changed no repository source or test files. The author added deterministic public-API regression cases to the package.

## Ownership conclusion and limits

Every exported module has identified local suite ownership, including the previously missing liveness boundary now repaired. The schema and lifecycle findings demonstrate why source-level inspection is necessary beyond matching filenames. Pure ports and callable aliases are qualified by consumers/reference implementations; platform implementations have no portable behavior in this package and remain adapter-owned. No current App test is a safe substitute for these SDK regressions, and no App test was removed.

The remaining external requirements are explicit: real server authorization/routing/persistence/replay, independently adopted immutable contract artifacts, release compatibility and supported cross-surface profiles, OS credential storage/network behavior, and Flutter interaction/accessibility. Proposal examples and a green unit suite cannot close those requirements. A machine-checked per-export Dart ownership manifest was not added; this human-reviewed inventory supplies current ownership evidence without asserting future automatic completeness.

## Maintaining the inventory

Local candidate verification used Dart 3.13.0: all 394 tests passed across 42
test files; strict analysis reported no issues; the contract validator accepted
all 24 JSON documents. The 21 new tests and corrected immutable-field test run
in package CI on Dart 3.8.0 and stable. Final per-commit CI evidence is attached
to [PR #7](https://github.com/kumwe/dart-sdk/pull/7); passing local checks do not
replace that matrix or the external requirements above.

Every added or changed public module must update this table and keep portable behavior, boundary and conformance regressions in the SDK suite. Review actual assertions, not only test filenames: the original immutable-field case illustrates why a named test is insufficient evidence. Runtime discovery or a future manifest gate may automate the inventory; this report does not claim that automatic enforcement exists.
